# Data-quality findings and repairs

Scope: source-code review plus the synthetic fixture generated by
`scripts/generate_demo.py`. No claims here are measured on the full Olist dataset.

| Risk in original implementation | Effect | Repair and evidence |
|---|---|---|
| Customer and seller metrics joined unaggregated reviews | Repeated money and item counts | Aggregate at the intended order grain; multi-review order remains BRL 165 |
| CLV grouped by stable customer plus state | Moving customer split into multiple rows | Latest-location dimension joined to stable identity; one row with BRL 308 |
| Daily windows omitted zero-order days | A "7-day" window meant seven sales dates | Dense 45-day fixture calendar; Jan 7 rolling average is BRL 26.71 |
| Incremental cutoff ran before rolling calculation | Refresh-boundary values changed; old corrections were missed | Full daily rebuild; historical correction regression |
| `MAX(payment_type)` was described as a mode | Alphabetical winner, not dominant type | Count descending, payment value descending, name tie-break |
| Seller reviews averaged at item grain | Multi-item orders overweighted satisfaction | Seller/order rollup; fixture mean 3.89 |
| Missing estimate was counted as not late | Inflated on-time rate | Unknown remains null; denominator is 8 observed delivered orders |
| Early deliveries lost signed date difference | Early/on-time comparisons unreadable | Signed estimate difference; fixture returns -2 days |
| Customer location used independent lexical maxima | City/state could be unrelated and outdated | One latest source row supplies the pair |
| Geolocation `any_value` called "most frequent" | Nondeterministic description and output | Rank city/state pairs by frequency, with deterministic ties |
| Numeric ZIP inference | Leading zero lost | Explicit text contract; `01001` survives |

High-severity issues are duplicated revenue, customer grain and rolling-window
errors. Missing delivery comparisons and item-weighted reviews materially bias
service metrics. Location, payment mode and ZIP handling affect segmentation.

Expected imperfections are preserved: repeated review IDs and multiple reviews
per order are allowed; untranslated and missing product categories remain visible;
an order can have no item/payment/review rows. No false uniqueness constraint is
imposed on review IDs, and no mandatory category-translation relationship is added.

Tests check entity keys, composite item/payment keys, relationships, allowed
statuses, score ranges, order coverage, nonnegative financial fields, model grain,
and independent raw-to-mart revenue reconciliation. Source contracts are in
`models/staging/_sources.yml`; analytical contracts are in `models/schema.yml`.

Freshness is intentionally not asserted for a static historical dataset. Real
ingestion needs ingestion timestamps and source-specific freshness expectations.
